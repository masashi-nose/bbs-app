# Issue テンプレート

種類に合ったテンプレートを使う。該当する情報がない見出しは、無理に埋めずに削除してよい（空欄の見出しは読み手のノイズになるため）。分からない点は「要確認」と書く。

## バグ（`bug`）

```markdown
## 概要
<何が起きているかを1〜2文で>

## 再現手順
1. 
2. 
3. 

## 期待する動作
<本来どうなるべきか>

## 実際の動作
<実際にどうなるか。エラーメッセージやログがあればコードブロックで>

## 該当箇所
- `src/...:行番号` — <関係する理由>

## 環境
- ブラウザ / OS:
- 環境: ローカル（SQLite） / 本番（Vercel + Postgres）

## 補足
<原因の推測、修正方針の案、関連 issue など>
```

## 機能追加・改善（`enhancement`）

```markdown
## 背景・目的
<なぜ必要か。どんな課題を解決するか>

## やりたいこと
<追加・変更する内容>

## 完了条件
- [ ] 
- [ ] 

## 実装メモ
<影響範囲（エンティティ、マイグレーション、Server Actions、画面）や実装方針の案>

## 補足
<参考リンク、関連 issue、検討事項など>
```

## ドキュメント（`documentation`）

```markdown
## 概要
<どのドキュメントに何を追加・修正するか>

## 対象
- `README.md` など

## 作業内容
- [ ] 
- [ ] 

## 補足
```

## タスク・その他

```markdown
## 概要
<何をするか、なぜ必要か>

## 作業内容
- [ ] 
- [ ] 

## 完了条件
- [ ] 

## 補足
```
